Product tour

Follow risk from ingestion to evidence.

01 · Build the graph

Ingest an SBOM and inspect live graph totals.

Upload a CycloneDX JSON document, follow ingestion progress, and see application, package, dependency-edge, statement, and graph-node totals from the persisted model.

02 · Understand scope

Application overview

Review direct and transitive dependencies, graph size, vulnerable packages, and vulnerability totals for the selected application.

03 · Inspect packages

Dependency inventory

Separate direct packages from transitive packages and inspect the immediate graph context of each installed dependency.

04 · Review advisories

Move from vulnerability rows to complete advisory detail.

Join installed packages to normalized OSV advisories, then open the complete advisory content, affected versions, fixes, CVSS data, timestamps, and references.

05 · Trace sources

Keep advisory references connected to affected packages.

References remain dedicated graph resources and are grouped by advisory alongside the installed package versions they describe.

06 · Explain CVE impact

Start with cross-application scope, then follow the exact path to a fix.

Group one vulnerability across applications, center it between impacted dependency paths and provided fixes, and open focused node or advisory detail without losing context.

07 · Query the graph

SPARQL workbench

For developers, researchers, and graph practitioners

Run read-only SPARQL queries to inspect relationships, validate the graph model, and export custom results.

08 · Inspect grounding

AI Workbench evidence

Review Buggy's summary beside ranked advisory chunks, source identifiers, similarity scores, and complete evidence text.

Graph traversal

Affected-package relationship

Explore follows direct and transitive dependency occurrences, then reads the persisted vulnerability relationship on the affected package. 

ApplicationOccurrence
    │
    └── risk:dependsOn
            ▼
     PackageOccurrence
            │
            ├── risk:dependsOn
            │       ▼
            │  PackageOccurrence
            │
            └── risk:affectedBy
                    ▼
              Vulnerability
The graph is authoritative

No second vulnerability database is maintained for Explore.

Writes are explicit

Opening an application never silently invokes OSV enrichment.

Reads are scoped

Application views follow persisted dependency relationships from the selected occurrence.

Grounding is explicit

Buggy uses graph tools, while evidence answers retain source text, identifiers, and scores.

Quick start

From clone to graph.

Build locally with Maven or use Docker to package the frontend, backend, and persistent graph-data configuration together.

JDK 25+ Docker workflow Internet for first build No separate Node required
terminal 
# Build backend and frontend
$ ./mvnw clean package

# Start the application
$ java -jar target/dependency-risk-graph-0.0.1-SNAPSHOT.jar

# Or build and run everything with Docker
$ ./run.sh

# Open the application
→ http://localhost:8080
